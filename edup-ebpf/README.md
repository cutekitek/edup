# XDP datapath

Программа `edup` содержит карты `CONFIG`, `USERS`, `NAT_OUT`, `NAT_IN`, `STATS`.
Она не требует userspace-процесса после загрузки. Рабочий загрузчик, закрепление
карт/link и TOML-конфигурация — следующий этап (`edup-server`).

## Сборка и проверка

Проверено: WSL Arch Linux, ядро `6.18.33.2-microsoft-standard-WSL2`,
Rust `nightly-2026-09-26`, `bpf-linker 0.11.1`. Требуется BPF ISA v3 (cmpxchg);
на других ядрах загрузку нужно проверять отдельно.

```sh
rustup toolchain install nightly-2026-09-26 --profile minimal --component rust-src
# bpf-linker: готовый бинарник 0.11.1 из официального релиза Aya, в PATH.
sh scripts/check-xdp.sh
```

[Установка bpf-linker](https://github.com/aya-rs/bpf-linker#installation).
Сборка eBPF отдельно:

```sh
cargo +nightly-2026-09-26 build --locked -p edup-ebpf \
  --target bpfel-unknown-none -Z build-std=core --release
```

Артефакт: `target/bpfel-unknown-none/release/edup-ebpf` (ELF).
В Windows обычные `cargo test` и `cargo fmt --all` работают с общим крейтом;
eBPF собирается и проверяется в Linux/WSL. Не включайте feature `aya` при
сборке eBPF: это userspace-зависимость для Linux.

`xdp_check` загружает ELF через Aya и использует `BPF_PROG_TEST_RUN` в реальном
ядре. Он не прикрепляет программу к интерфейсам, не закрепляет карты, не меняет
маршруты. Проверяются TCP/UDP/ICMP echo в обе стороны, контрольные суммы, TTL,
MTU, обфускация, KEEPALIVE, роуминг, отбрасывание неверных пакетов, прозрачность
для ARP/SSH, коллизии/исчерпание NAT, состояния TCP и восстановление после
независимого удаления записей двух LRU-карт. На только что запущенном ядре
проверка таймаута может ждать до 31 секунды. Ошибка любой проверки завершает процесс
с ненулевым кодом. Для проверки реального XDP_TX нужен отдельный veth/VPS-стенд.

## Ограничения текущего этапа

- Ethernet без VLAN, IPv4 снаружи без options; IPv4 options внутри сохраняются.
- Только TCP, UDP и исходящий ICMP echo request / входящий echo reply.
  Фрагментированные туннельные/внутренние пакеты отбрасываются; чужой трафик
  и входящие пакеты без активной NAT-записи передаются стеку хоста.
- UDP checksum внешнего пакета равен нулю. Внутренние checksum обновляются
  инкрементально; полная проверка входных IP/L4 checksum не выполняется.
- Область XOR ограничена 1536 байтами; обычный внешний MTU — 1500, внутренний — 1464.
- NAT ищет до 64 портов от начального хэша; при исчерпании проб пакет теряется.
  NAT_IN определяет владельца и таймаут, NAT_OUT служит индексом. Обе стороны
  сверяют карты; при независимом вытеснении возможна потеря текущего соединения.
- Выделение порта защищено BPF_NOEXIST, таймаут — CAS по last_seen. Карты не
  образуют общую транзакцию; стресс-проверка конкурентных выделений/вытеснений
  на нескольких CPU пока не выполнена. Производительность также не измерялась.
- NAT-диапазон должен быть исключён из локального диапазона портов хоста.
  До запуска на VPS загрузчик должен валидировать конфигурацию и сетевые условия.

Структуры карт остаются в `edup-common`; к существующим счётчикам добавлен `pass`.
Все поля `*_be` — сырые значения network order, другие числовые поля — host order.
