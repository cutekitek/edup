# Запуск edup TUN-клиента на Windows

Для этого сервера подготовлена папка `C:\projects\edup\local\windows-client`:

- `edup-client.exe` — release-сборка Windows x64;
- `wintun.dll` — подписанная AMD64 DLL Wintun 0.14.1;
- `client.toml` — готовая конфигурация с индивидуально сгенерированным паролем;
- `WINTUN-LICENSE.txt` — лицензия распространяемой DLL.

Папку можно целиком перенести, например, в `C:\edup`. DLL должна оставаться
рядом с EXE. `client.toml` содержит секрет: не публикуйте его и не добавляйте
в репозиторий. Каталог `local/` исключён через `.gitignore`.

## 1. Откройте PowerShell от администратора

В меню «Пуск» найдите PowerShell → «Запуск от имени администратора».
Завершите другие VPN, которые устанавливают маршруты `0.0.0.0/1` и
`128.0.0.0/1`; edup не заменяет их автоматически.

```powershell
Set-Location C:\projects\edup\local\windows-client
.\edup-client.exe --config .\client.toml check
.\edup-client.exe --config .\client.toml run
```

При переносе папки измените только путь в `Set-Location`.
После `client ready: edup0 10.66.0.7` оставьте окно открытым.
Это сообщение подтверждает локальный запуск; связь проверяется следующим шагом.

## 2. Проверьте подключение в другом окне PowerShell

```powershell
Get-NetIPAddress -InterfaceAlias edup0 -AddressFamily IPv4
Get-NetRoute -InterfaceAlias edup0 -AddressFamily IPv4
ping -4 1.1.1.1
curl.exe --noproxy "*" -4 https://1.1.1.1/cdn-cgi/trace
```

Должен появиться адрес `10.66.0.7`, маршруты `/1`, ответы ping.
В ответе `curl` ожидается строка `ip=195.58.134.147`.
При проверке используйте `-4`: клиент туннелирует только IPv4.
DNS-настройки и IPv6 не меняются; более специфичные маршруты к локальной сети
сохраняются. Это не режим блокировки всего трафика вне туннеля.

Параметры готовой конфигурации:

| Параметр | Значение |
|---|---|
| Сервер | `195.58.134.147:7777`, UDP |
| Пользователь | `7` |
| Туннельный адрес | `10.66.0.7` |
| Имя интерфейса | `edup0` |
| MTU | `1400` |
| KEEPALIVE | Каждые 15 секунд |

Пароль уже записан в `client.toml`. Одновременно используйте этот ID только
на одном устройстве: сервер запоминает последний endpoint пользователя.

В готовом Windows-конфиге MTU — 1400: проверены ping с соответствующим размером
и загрузка 10 МБ через VPS. MTU 1464 на текущем пути не прошёл проверку больших
пакетов. Значение 1200 использовалось для ранней TCP-проверки WSL, но слишком
мало для QUIC: ему нужен UDP payload минимум 1200 байт, то есть IPv4 MTU
не менее 1228. См. [RFC 9000 §14.1](https://www.rfc-editor.org/rfc/rfc9000.html#section-14.1).
MTU клиента должен также учитывать внешние 36 байт edup.

При подготовке на этой Windows обнаружен работающий адаптер `throne-tun`.
Перед запуском edup отключите TUN-режим другого VPN, чтобы маршруты и выбор
физического пути не конфликтовали.

## 3. Остановите клиент

Нажмите **Ctrl+C** в окне с `run` и дождитесь завершения. Клиент удалит свои
маршруты, закроет TUN и выведет счётчики. Не закрывайте процесс через диспетчер
задач, если доступен Ctrl+C: принудительное завершение не выполняет очистку.

## Если не запускается или нет трафика

- **`The parameter is incorrect. (os error 87)`** в первоначальной сборке:
  исправлено применение MTU 1200 к IPv6 при создании TUN. Обновлённый клиент
  задаёт MTU только для IPv4; используйте актуальные EXE и конфигурацию.
  Создание и удаление настоящего Wintun с этим MTU проверено из Administrator.
- **`wintun.dll missing`**: DLL должна лежать рядом с EXE. Готовая папка уже
  содержит её. При самостоятельной сборке используйте официальный архив
  [Wintun](https://www.wintun.net/), файл `bin/amd64/wintun.dll` для x64.
- **Ошибка доступа/создания TUN**: запустите PowerShell от администратора.
- **`adapter edup0 already exists`**: остановите предыдущий edup-клиент.
  Клиент намеренно не использует существующий адаптер другого процесса.
- **`route ... already exists`**: остановите конфликтующий VPN; не удаляйте
  маршруты другого приложения вручную.
- **`client ready`, но нет ответов**: проверьте совпадение конфигурации и
  доступность UDP 7777. `Test-NetConnection -Port 7777` проверяет TCP и
  здесь не подходит. После Ctrl+C смотрите `keepalive_rx`; ноль означает,
  что валидных ответов KEEPALIVE не получено.
- После изменения Wi-Fi/физической сети перезапустите клиент.
- **Старая сборка: сайты зависают, Speedtest не получает серверы**: исправлен
  порядок чтения Wintun. Ожидание события до проверки очереди оставляло TCP ACK
  непрочитанными. Обновите EXE и установите `mtu = 1400`. Проверено: 10 МБ за
  1,95–5,07 с, список серверов Speedtest — HTTP 200 за 0,64 с. Скорость зависит
  от текущего пути; это результаты диагностических запусков, не гарантированный лимит.

Для периодических счётчиков во время диагностики:

```powershell
$env:EDUP_DIAGNOSTICS = '1'
.\edup-client.exe --config .\client.toml run
# После остановки клиента:
Remove-Item Env:\EDUP_DIAGNOSTICS
```

Счётчик `dropped` включает неподдерживаемые пакеты (например, IPv6), а не только
ошибки передачи. Не интерпретируйте его как процент потерь сети.

После аварийного завершения сначала убедитесь, что edup больше не работает:

```powershell
Get-Process edup-client -ErrorAction SilentlyContinue
Get-NetRoute -AddressFamily IPv4 |
    Where-Object RouteMetric -eq 42760 |
    Format-Table DestinationPrefix, InterfaceAlias, InterfaceIndex, NextHop, RouteMetric
```

После проверки списка можно удалить оставшиеся маршруты именно этого клиента.
Следующая команда ограничивает выбор метрикой и тремя используемыми префиксами
и запросит подтверждение для каждой записи:

```powershell
Get-NetRoute -AddressFamily IPv4 -PolicyStore ActiveStore |
    Where-Object {
        $_.RouteMetric -eq 42760 -and
        $_.DestinationPrefix -in @('195.58.134.147/32', '0.0.0.0/1', '128.0.0.0/1')
    } | Remove-NetRoute -Confirm
```

## Управление сервером

```powershell
ssh root@195.58.134.147 "systemctl status edup-server --no-pager"
ssh root@195.58.134.147 "/usr/local/sbin/edup-server stats"
ssh root@195.58.134.147 "/usr/local/sbin/edup-server users"
```

На сервере конфигурация находится в `/etc/edup/server.toml`, юнит —
`edup-server.service`. Остановка: `systemctl stop edup-server`.
Запуск: `systemctl start edup-server`. Применение изменений:
`systemctl reload edup-server` — оно сбрасывает NAT и текущие соединения.
Для автозапуска используется `systemctl enable edup-server`.

edup использует обфускацию по паролю, а не криптографическое шифрование.
