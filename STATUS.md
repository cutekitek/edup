## Цель

Лёгкий L3-туннель поверх UDP. Криптографии нет, только простая обфускация по
паролю (считаем, что злоумышленников на линии нет).

- **Сервер** — Linux VPS, весь путь данных в XDP (вариант 2), трафик не попадает
  ни в userspace, ни в сетевой стек ядра.
- **Клиент** — Windows и Linux, TUN-режим.

## Зафиксированные решения

- Язык: Rust везде. eBPF на Aya (`aya-ebpf` 0.2.1, `aya` 0.14, `aya-build` 0.2).
- Сервер: одна XDP-программа на `eth0`, в обе стороны `XDP_TX` (у VPS один NIC и
  один шлюз, MAC-адреса просто меняются местами). Весь «чужой» трафик (SSH, ARP,
  трафик хоста) — `XDP_PASS`.
- Рукопожатия нет, конфигурация статическая: у каждого пользователя постоянный ID,
  туннельный адрес = `tun_net + id`. Первый валидный пакет от клиента запоминает
  его endpoint (так же работает роуминг).
- Ключ обфускации один на сервер, выводится из пароля (BLAKE2s).
- В userspace на сервере только разовый загрузчик: загрузить программу, заполнить
  карты, прикрепить, закрепить link и карты в `/sys/fs/bpf/edup/`, выйти.
- NAT в BPF: endpoint-independent mapping; две `LRU_HASH` карты (out/in);
  выделение порта по хэшу с вставкой `BPF_NOEXIST`; ленивые таймауты по
  `last_seen`.
- Порты: диапазон NAT отделён от локальных портов хоста
  (`net.ipv4.ip_local_port_range` вынести за пределы NAT-диапазона).
- MSS clamping делается на клиенте, а не на сервере.
- Первая фаза: только IPv4 внутри и снаружи; TCP, UDP, ICMP echo.

## Формат пакета (реализован в `edup-common/src/wire.rs`)

```
+--------------------------------+
| Nonce (4 байта, открыто)       |
+--------+--------+--------------+
| Type/  | Magic  | User ID (BE) |  ← XOR
| Flags  | 0xED   |              |
+--------+--------+--------------+
| Внутренний IPv4-пакет          |  ← XOR
+--------------------------------+
```

- Накладные расходы: 8 байт заголовка, вместе с внешними IPv4 и UDP — 36 байт.
  MTU туннеля 1464 при внешнем MTU 1500.
- Типы: `0` — DATA, `1` — KEEPALIVE (сервер отвечает таким же пакетом).
- Поток ключа: SplitMix64 в режиме счётчика, слово `i` = `mix64(seed + (i+1)*GOLDEN)`,
  `seed = k0 ^ mix64(k1 ^ nonce)`. Байты слова в little-endian.
- Лимит `MAX_KS_WORDS = 192` слов на пакет (ограничение для верификатора).

### Исправление скорости Windows 2026-09-27

- Причина зависаний TCP: путь `tun-rs 2.8.11 recv_intr_timeout` ожидает событие
  перед проверкой очереди Wintun. Исправлено на `try_recv` до ожидания, чтобы
  дренировать уже поступившие пакеты, включая ACK. Регрессия на настоящем Wintun:
  старый путь оставлял 10 из 32 пакетов, новый успешно читает две пачки по 32.
- UDP-сокет запрашивает буферы 4 МиБ RX / 1 МиБ TX. `EDUP_DIAGNOSTICS=1`
  выводит счётчики каждые 5 секунд. Для Windows-конфига выбран проверенный MTU
  1400; внешний размер 1500 не прошёл ping, а старый MTU 1200 слишком мал для QUIC.
- Проверка напрямую через Windows Wintun и VPS: до исправления загрузка 10 МБ
  обрывалась по таймауту 20 с после части файла, после — полный файл за
  1,95–5,07 с. API списка серверов Speedtest: HTTP 200, 5 серверов, 0,64 с.
  Тест использовал отдельные `/32` к проверяемым узлам, сеть остальных приложений
  не переключалась. Временные адаптеры и маршруты удалены.
- Дополнительно XDP_TX дополняет короткие Ethernet-кадры нулями до 60 байт
  без FCS (включая TCP ACK и KEEPALIVE); это проверяется пакетными регрессиями.
  Исправленная программа развёрнута на VPS. Порт остался UDP 7777; проба UDP 8443
  не устранила зависания и завершена. Трассировщики остановлены.

### 2. `edup-server` — загрузчик (Linux), реализовано
- [x] `build.rs` через `aya_build::build_ebpf`.
- [x] TOML-конфиг: интерфейс, `server_ip`, `nat_ip`, порт, пароль, `tunnel_net`,
      NAT-диапазон портов, `max_frame`, режим XDP, список пользователей.
- [x] Команды: `up` (загрузить, заполнить карты, прикрепить, закрепить, выйти),
      `down` (открепить и удалить закреплённое), `reload` (обновить карты),
      `stats` (сумма per-CPU счётчиков), `users` (endpoint'ы).
- [x] systemd-юнит (oneshot) для запуска при загрузке.
- [x] Дополнительная команда `check` для проверки TOML без root, в том числе на Windows.

Загрузчик валидирует сеть/ID, MTU, NAT-диапазон, его непересечение с портом
туннеля и `ip_local_port_range`, а также текущие TCP/UDP-сокеты хоста.
Карта `STATS` содержит 16 элементов. Карты и программа закрепляются под
`/sys/fs/bpf/edup/gen_<program-id>_<ifindex>_<mode>/`, link — в `.../link`.
`reload` подготавливает новое поколение и атомарно переключает link:
**каждый reload сбрасывает NAT, endpoints, счётчики и текущие соединения**.
Ошибки до переключения сохраняют старую конфигурацию. Смена интерфейса/режима
требует `down/up`. Автоматического перехода с native на generic XDP нет.
Системные сетевые настройки загрузчик не меняет. Установка юнита и запуск
на VPS проверены, автозапуск включён; перезагрузка VPS ещё не проверена.
